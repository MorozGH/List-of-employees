# Список сотрудников

Веб-приложение со списком сотрудников: регистрация/вход, поиск по ФИО, фильтр по отделу, добавление сотрудника. Данные хранятся в SQLite и сохраняются после перезапуска.

> Тестовое задание. Исходный текст — в [`tasks/`](tasks/).

## Стек

- **Frontend:** React 19 + TypeScript (Vite), обычный CSS
- **Backend:** Node.js + Express 5 + TypeScript
- **База данных:** SQLite (better-sqlite3), файл `server/data/employees.db`
- **Авторизация:** email + пароль (bcrypt-хеши, bcryptjs), JWT (jsonwebtoken)
- **Валидация:** zod на сервере + проверка обязательных полей на клиенте

## Быстрый старт

Требования: **Node.js 20+** и npm.

```bash
npm install
npm run dev
```

- Клиент: http://localhost:5173
- API: http://localhost:3001 (запросы `/api` проксируются Vite)

При первом запуске база создаётся автоматически и заполняется **5 демонстрационными сотрудниками**. Зарегистрируйте любого пользователя на странице входа — и список откроется.

Данные (пользователи и сотрудники) хранятся в файле БД и переживают перезапуск приложения. Чтобы начать с чистого листа, удалите `server/data/employees.db*` при остановленном сервере.

## API

Все маршруты `/api/employees` требуют заголовок `Authorization: Bearer <token>`.

| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/auth/register` | регистрация `{ email, password }` → `{ token, user }` |
| POST | `/api/auth/login` | вход → `{ token, user }` |
| GET | `/api/auth/me` | текущий пользователь (проверка токена) |
| GET | `/api/employees?search=&department=` | список; поиск по ФИО (без учёта регистра), фильтр по отделу |
| GET | `/api/employees/departments` | список отделов для фильтра |
| POST | `/api/employees` | добавление `{ fullName, position, department }` (все поля обязательны) |

Ошибки возвращаются как `{ error: string }` с кодами 400/401/409/500.

## Что проверено

Сценарии проверены вручную через API и браузер (Node 22/24, Windows):

- регистрация, вход, выход; повторная регистрация email → 409; неверный пароль → 401;
- доступ к списку и API без токена → 401; истёкший/битый токен → авто-разлогин;
- поиск по ФИО без учёта регистра (в т.ч. кириллица в нижнем регистре);
- фильтр по отделу; пустой результат показывает явное сообщение;
- добавление сотрудника: ошибки под пустыми полями, новый отдел появляется в фильтре;
- персистентность: после перезапуска сервера пользователи, сессия и сотрудники сохраняются;
- `npm run build` — тайпчек и сборка обоих пакетов без ошибок.

## Решения и особенности

- **Пароли** — только bcrypt-хеши (cost 10); в БД и логах паролей нет.
- **Поиск по кириллице без учёта регистра**: SQLite `lower()`/`NOCASE` работают только с ASCII, поэтому рядом с `full_name` хранится `full_name_lower`, вычисленный средствами JS.
- **SQL** — только параметризованные запросы (защита от инъекций).
- **JWT** хранится в localStorage; при 401 клиент разлогинивает. Выход — удаление токена.
- **Дизайн** — обычный CSS с токенами в [`DESIGN.md`](DESIGN.md), без UI-библиотек.
- Конвенции кода — [`AGENTS.md`](AGENTS.md) и [`docs/typescript-nodejs-react-vite.mdc`](docs/typescript-nodejs-react-vite.mdc).
